# Прототип игрока — меню слева

Открыть `index.html` в обычном браузере. Все файлы рядом; сервер, Unity, сеть и установка зависимостей не нужны. Это отдельное продолжение этапа 2. Прототип мастера и игровые файлы не изменены.

## Основное решение

Слева полноценное меню игрока, а не пустой набор мастерских разделов. Группа «На карте»: выбор/перемещение, линейка, области, отметки/ластик. Группа «За столом»: мой персонаж, кубики, журнал, справочник. Настройки инструмента раскрываются **внутри левого меню, прямо под его кнопкой**. Отдельной горизонтальной строки инструментов нет. Над картой остаётся компактная очередь ходов только для просмотра. Участники доступны из заголовка.

## Что попробовать

1. «Линейка» слева → протянуть ЛКМ по карте. Измерение остаётся до очистки; масштаб условный: 40 экранных px = 5 фт. Это демонстрация UX, не точная игровая линейка.
2. «Области» → круг/квадрат/конус → клик по карте. В прототипе размеры фиксированы; нет расчёта целей, клеток или автоматического урона. Формы показаны условно.
3. «Отметки / ластик» → выбрать эффект → кликать клетки. Ластик убирает близкие собственные демоотметки. Очистка требует подтверждения; область измерения — отдельный объект.
4. «Выбор» → свой токен «Эллиан» → «Информация» или ПКМ. Можно перетаскивать свой токен; чужие — только выбирать и смотреть. У Гоблина ХП/КД не опубликованы; закрытых чисел нет даже в демоданных. Карточка токена не даёт редактировать боевые параметры мастера.
5. «Мой персонаж» открывает отдельный локальный лист, вкладки переключаются, заметки можно менять. Заметки живут в памяти страницы и сбрасываются при обновлении. Это предложенный вход в существующий лист; в общем игровом заголовке текущего проекта кнопка персонажа отключена. Полный редактор и LSS импорт/экспорт не подключены.
6. «Кубики» раскрывает кнопки d4–d100 прямо в меню. Результат демоброска случайный и попадает в «Журнал бросков». Удаление своих кубиков показано подтверждением, без удаления журнала; физических кубиков в прототипе нет.
7. «Справочник» → поиск по двум опубликованным демозаписям. Записи только для чтения. Мастерской библиотеки, редактора статблоков и приватных записей нет. Публичный статблок открывается в карточке соответствующего токена.
8. В верхней полосе **прототипа**, отдельно от меню продукта, «Демо: запрос перемещения» показывает проверку рискованного маршрута → подтверждение → ожидание мастера / отмена. Игрок не разрешает собственный запрос. Маршруты, таймеры и мастерские решения не вычисляются.
9. Esc: модальное окно → выход из ввода → завершение инструмента → закрытие панели → закрытие меню на узком экране → снятие выделения. ПКМ при активном инструменте завершает его. Одна содержательная панель за раз; клики по ней не проходят в карту.
10. На окне ≤850 px меню становится выдвижным слева. После выбора инструмента оно закрывается для работы на карте; «Меню игрока» снова открывает настройки выбранного инструмента. Открытая нижняя карточка и открытое боковое меню блокируют указатель карты. Это предложенная адаптация, визуально в браузере пока не проверена.

## Что взято из проекта

- `DiceUI.cs`: линейка, круг/квадрат/конус, закраска/ластик, эффекты, физические кубики и журнал.
- `TokenController.cs`, `NetworkPermissions.cs`: различие перемещения/просмотра и мастерских параметров, разрешённые публичные поля, права на объекты. Прототип сознательно проверяет простой пример «свой можно двигать, чужой нельзя». Это не универсальное правило игры: там мастер может разрешить общее управление. Редактирование мастерских ХП/КД не выдаётся владельцу токена.
- `PublicReferenceLibrary.cs`: доступный игрокам справочник только для чтения, приватные записи не передаются.
- `CharacterSheetUI.cs`: локальный лист, вкладки и LSS. `InitiativeTracker.cs`: мастер управляет очередью, игрок её видит. `MovementReviewUI.cs`: игрок подтверждает/отменяет рискованное перемещение, мастер решает запрос.

Левое меню, раскрытие под кнопкой, размещение карточек и узкий режим — **предлагаемый UX**, а не текущая реализация игры. Геометрия, туман, смена сцен, права и следующий ход игроку не показываются. Полные функции и окончательное оформление не подключались.

## Проверка

`node --check player.js` и `node check-player.cjs`: 15 проверок логики и обработчиков, PASS; результат в `verification.json`. Проверены одиночный инструмент и раскрытие его параметров слева, видимость полей, отсутствие мастерских действий, свой/чужой токен, запросы, очередь только для просмотра, лист, справочник, кубики/журнал, разметка, линейка, Esc и логика узкого режима.

Проверки используют минимальный DOM-адаптер, не настоящий браузер. CSS, реальные жесты и читаемость на экране не подтверждены. Ранее встроенный браузер отклонил локальный file://; обход ограничения не выполнялся. Скриншот не выдаётся за проверенный результат.

Все данные демонстрационные, хранятся только в памяти. Этапы финального оформления и подключения игры не начаты.
