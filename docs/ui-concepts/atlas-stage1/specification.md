# Этап 1: схема стола мастера для согласования

4 ноября 2026. Основа — одобренный atlas-v2. Результат: статические SVG, HTML и PNG, спецификация. Здесь согласуется предлагаемое поведение. Прототип, изменения игровых файлов и последующие этапы не выполнялись.

## Области схемы

| Область | Решение для согласования |
|---|---|
| A — сессия | Активная сцена, роль, участники/код, файловые операции сессии, настройки. Название сцены открывает тот же список, что раздел «Сцены». Без облачного каталога. |
| B — разделы | Стол, сцены, токены, библиотека, мой лист, игроки, выход. Библиотека объединяет входы в существующие статблоки и справочник. |
| C — инициатива | Одна горизонтальная строка: раунд, участники с числами, следующий ход мастера. Переполнение прокручивается внутри строки; «список» открывает полное редактирование. Сворачивание сохраняет индикатор текущего хода и кнопку возврата. |
| D — инструменты | Выбор, создание токена, линейка, области, отметки, геометрия, туман, карта, переходы доступны и во время боя. Категория раскрывает подинструменты, а не другой режим игры. |
| E — контекст | Одна строка параметров текущего инструмента. В обычном выборе её нет. Для тумана — включение, раскрытие/закрытие, пауза, предпросмотр/источник, отмена, завершение. Расширенные команды истории и восстановления — в меню тумана. |
| F — карта | Основное пространство. Панели перехватывают клики внутри себя. Геометрия, туман и выбранный токен имеют разные видимые обозначения. |
| G — инспектор | Временная карточка выбранного токена, привязана к свободному краю рядом с ним и ограничена границами окна. Три вкладки: параметры, доступ, статблок. Полные свойства открываются в той же области, не второй колонкой. |
| H — нижние доки | Кубики, журнал бросков и число запросов перемещения. Журнал раскрывается локально снизу. Открытие журнала не меняет очередь ходов. |

## Панели и открытие

Это **предложения UX**, а не описание уже реализованной компоновки.

- Один клик по токену в режиме «Выбор» выделяет его и показывает явную кнопку «Информация». Эта кнопка открывает G. ПКМ сохраняет быстрый доступ к существующим действиям. Перетаскивание в режиме выбора перемещает токен в пределах существующих прав.
- В активном инструменте клик по карте выполняет инструмент, включая попадание на клетку с токеном; он не выбирает токен. Для выбора нажать «Выбор». Уже открытая карточка может оставаться для чтения; её собственные поля и кнопки перехватывают ввод.
- Сцены, список токенов, библиотека, локальный лист и участники открывают одну временную панель, заменяющую G. Последняя выбранная вкладка и прокрутка сохраняются локально. Закрытие возвращает карту без автоматического открытия прежней панели.
- Узкая панель списка сцен открывается слева поверх карты рядом с B; широкие формы библиотеки/листа занимают ограниченную центральную область со своей прокруткой. Ни одна из них не является постоянной правой колонкой.
- Список токенов позволяет открыть карточку токена; фокусирование камеры на токене здесь не заявляется, поскольку такое действие отдельно не подтверждено исходниками.
- × закрывает конкретную панель. Повторный клик по выбранному разделу закрывает её. Клик по свободной карте в режиме выбора снимает выделение и закрывает карточку; при несохранённом вводе сначала требуется применить или отбросить изменения.
- При смене токена/сцены или закрытии формы с несохранёнными значениями предлагается «Применить / Отбросить / Остаться». Поля проверяются перед применением; ошибка остаётся рядом с полем. Для существующих черновиков библиотек сохраняется их семантика.

## Основные сценарии

1. **Токен и ХП.** «Выбор» → токен → «Информация» → параметры. Текущее/максимальное ХП и КД редактируются полями, рядом быстрое изменение ХП −5 / ввод дельты / +5. Кнопка «Применить» выполняет серверную операцию; отрицательное значение дельты означает урон. Дельта не должна применяться вторично по повторному Enter. Неверный ввод не меняет токен. Доступны состояния, изображение, имя, герой/NPC, скрытие и права в соответствующих вкладках/полных свойствах. Изменение ХП не является автоматической атакой или расходом способности.
2. **Инициатива.** Из токена — «Добавить в инициативу». В полном списке — существующее добавление участника, изменение инициативы/ХП и удаление. Назначение результата d20 явно показывает ожидание следующего броска и отмену. «Следующий ход» доступен мастеру, переносит активность и обновляет раунд по существующей логике. Очистка требует существующего подтверждения; общего отката этой операции не обещаем.
3. **Туман в бою.** «Туман» → «Раскрыть» или «Закрыть» → кисть на карте. Начало этого инструмента прекращает другой активный инструмент, но не бой. Включение тумана и пауза автоматического раскрытия — отдельные действия. «Глазами игроков» явно отмечает предпросмотр и источник обзора; мастер не перемещает токены в предпросмотре. «Завершить» или Esc выходит из кисти, не отключая сам туман. Отмена вызывает существующую систему отмены, без обещания бесконечной истории.
4. **Геометрия в бою.** «Геометрия» → стена / дверь / открыть-закрыть / препятствие / колонна / стирание. В E появляются параметры выбранного инструмента, отмена и завершение. Действие на карте имеет явную подсказку; инструменты не активны одновременно с кистью тумана. Переключение завершает текущий жест, незавершённый предпросмотр отменяется.
5. **Сцены.** «Сцены» или имя сцены → список, пустая/копия, переименование/удаление через меню. Переключение вызывает существующее сохранение текущей сцены и сетевую загрузку, закрывает устаревшую карточку токена, прекращает локальный инструмент. Используется существующая индикация синхронизации; карта не принимает ввод до готовности. Последнюю сцену удалить нельзя. Переход и перенос выбранных токенов — отдельные существующие операции с подтверждением, не обычный клик по сцене.
6. **Кубики и журнал.** Нижний док → d4/d6/d8/d10/d12/d20/d100 создаёт физические кубики существующим способом; броски и суммы попадают в журнал. Удаление кубиков сохраняет существующую область прав и подтверждение. Не добавляем строку формул, автоматические проверки или автоматический урон.
7. **Библиотека.** Раздел → статблоки или справочник. Существуют создание/редактирование, импорт/экспорт справочника, поиск/теги/категории/закрепление/приватность; статблоки поддерживают импорт листа и настройку публичных полей. Не обещаем несуществующий универсальный экспорт статблоков. Редактор библиотеки заменяет текущую панель G; несохранённые правки обрабатываются явно.
8. **Мой лист.** Предлагаемый вход к существующему локальному CharacterSheetUI: характеристики/навыки, атаки, способности, снаряжение, заметки, импорт/экспорт LSS JSON. Это не возможность открыть полный лист любого игрока по токену. Общая кнопка «Персонаж» в текущем DiceUI отключена: её подключение — отдельное будущее решение.
9. **Запросы перемещения.** Индикатор показывает фактическое число ожидающих запросов. При ненулевом числе открывается существующее модальное рассмотрение с токеном, целевой клеткой и оставшимся временем; «Разрешить» / «Отклонить» — разовое решение. До разрешения токен остаётся на исходной клетке и карта не раскрывается. Закрытие панели не означает разрешение.

## Приоритет ввода

Предлагаемая однозначная модель для дальнейшей реализации:

1. Модальное подтверждение, файловый диалог, рассмотрение перемещения или синхронизация блокируют нижележащую карту и горячие клавиши. Это соответствует уже существующему GameplayInputGate; конкретное оформление новое.
2. Сфокусированное поле получает текст/числа, Enter применяет только это поле/форму, Esc сначала выходит из ввода или обрабатывает несохранённые значения. Горячие клавиши карты не работают при вводе.
3. Клик в панели принадлежит панели. Он не рисует туман, не двигает токен и не бросает кубик под ней.
4. На свободной карте действует ровно один инструмент. Переключение не переносит зажатую кнопку в новый инструмент: сначала отпускание, затем новый жест.
5. Esc закрывает верхнее модальное окно; иначе отменяет текущий незавершённый жест/инструмент; иначе закрывает открытую панель; иначе снимает выделение. Один Esc делает только один шаг. Повторное нажатие нужно для следующего уровня.
6. ПКМ на карте при активном инструменте завершает инструмент. ПКМ по токену открывает меню только в режиме «Выбор». Существующий gate уже учитывает модальные окна, поля, UI и кадр выхода, но полный порядок выше ещё не реализован и подлежит согласованию.

## Узкий экран и масштаб

Предлагаемые пороги указаны в **логических пикселях после масштаба UI**, проверка пока не выполнялась.

- От 1440: схема как на изображении, контекстная карточка ограничивается свободным местом карты.
- 1100–1439: разделы — компактные иконки с подсказками/именем при фокусе; менее частые инструменты в подписанном «Ещё». Туман, геометрия, выбор и токены доступны без поиска по настройкам. Очередь ходов прокручивается внутри своей строки.
- Менее 1100: B сворачивается в кнопку «Разделы», инициатива показывает текущего/следующего и «Все участники». D содержит основные категории с горизонтальной прокруткой. E допускает перенос на вторую строку. Это режим компромисса для настольного окна, не обещание мобильного интерфейса.
- Открыта одна панель/нижняя карточка на всю доступную ширину, с ограничением высоты и внутренней прокруткой; за ней карта не получает ввод. Одновременно журнал, лист и инспектор не раскладываются колонками. Закрытие возвращает предыдущий инструмент без возобновления зажатого жеста.
- Кнопки не уменьшаются до нечитаемого текста. Tab/Shift+Tab и видимый фокус обязательны; при открытии панели фокус внутри, при закрытии — на открывшей кнопке. Навигация контроллером отдельно не проектировалась.

## Решения на согласование

1. Горизонтальная инициатива и постоянная строка инструментов мастера, включая туман и геометрию во время боя.
2. Выбор токена → явная «Информация» → временная карточка; одна содержательная панель за раз.
3. Применение ХП/КД явно кнопкой, защита несохранённых полей, отсутствие автоматического урона.
4. Контекстная строка настроек без постоянной правой колонки; описанный порядок Esc/ПКМ и исключительность инструментов.
5. Новый вход «Мой лист» только к локальному листу и предложенная адаптация узкого окна.

После согласования можно отдельно разрешить этап 2 — интерактивный прототип. Настоящий артефакт не запускает этот этап.
