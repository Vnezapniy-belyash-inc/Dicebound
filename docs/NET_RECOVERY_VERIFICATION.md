## Повторное подтверждение снимков

Добавлено шесть проверок обработчиков:

- повтор текущей применённой ревизии планирует повторный ACK;
- старая ревизия не подтверждается;
- состояние, которое не было применено, не подтверждается;
- все три случая проверены отдельно для SceneEditor и FogManager;
- повтор не меняет флаг перерисовки и не применяет данные заново.

До исправления: **6 total, 4 passed, 2 failed**, `Logs/net-recovery-replay-before-result.json`. Оба падения — отсутствие ACK текущей применённой ревизии.
После исправления: **6/6 passed**, `Logs/net-recovery-replay-after-result.json`.
ACK по-прежнему отправляется обычным путём после готовности представления; обработчик повтора только планирует подтверждение.
Полная регрессия после изменения: **87 total, 86 passed, 0 failed, 1 skipped (Relay)**, `Logs/net-recovery-replay-regression.xml`. Прогон наблюдался по файлу отчёта, без вмешательства CLI в главный поток.

## Диагностика зависшего Relay при обрыве портрета

На настоящем Relay-соединении портрет 788399 байт/986 частей прерван сервером после получения клиентом 1 части. Клиент был под занавесом, ввод запрещён (`Logs/net-recovery-relay-portrait-incomplete.json`). Сервер удалил клиента ID 2, но клиент более 90 секунд оставался IsConnected=true; Relay повторял `allocation ID client mismatch`. Настроенный транспортный таймаут 30000 мс не вызвал обработчик отключения. Это отдельная воспроизведённая ошибка, а не успешная приёмка.

Добавлены запрос/ответ сервера раз в две секунды и завершение зависшего соединения после 30 секунд без подтверждённого ответа. Ответ проверяет отправителя и актуальную последовательность; прежние ответы не продлевают соединение. Автоматическое закрытие сохраняет штатное переподключение LobbyUI и Relay-код. Добавлены три проверки границы таймаута и настоящий UDP-тест запроса/ответа. Первые два полных прогона: 97 total, 95 passed, 1 failed, 1 skipped (`Logs/net-heartbeat-regression.xml`, `Logs/net-heartbeat-regression-rerun.xml`). Причина нового падения — захваченная локальная переменная обработчика теста не сохраняется при перезагрузке домена EnterPlayMode. Подготовка пустой сцены сама по себе не исправила падение; результат перенесён в поле теста. Изолированный настоящий запрос/ответ после исправления: **1/1 passed**, `Logs/net-heartbeat-isolated.xml`. Полный повтор: **97 total, 96 passed, 0 failed, 1 skipped (Relay)**, `Logs/net-heartbeat-regression-final.xml`. Player `build_cecd8aca292d`: Succeeded, 0 ошибок. Первая Relay-сессия потеряла аллокацию хоста (`AllocationInvalid`, NGO остановил сервер); этот запуск не принят. После подтверждения остановки создана новая сессия. Повторный запуск проверочного скрипта ожидал ID 1, тогда как после перезапуска сервер выдал ID 2; состояние проверено, сценарий продолжен с фактическим ID без повторного подключения клиента.

В новой сессии портрет прерван на 16/986 частях, занавес и ввод закрыты (`Logs/net-heartbeat-portrait-partial.json`). Автоматический вход ID 3 состоялся, но передача карты исчерпала клиентские повторы при сохранении живого соединения. Последний серверный прогресс был 512 частей, клиент очистил незавершённую карту; это отдельная незавершённая проблема согласования бюджетов повторов карты.

Затем отключён только серверный обработчик запроса heartbeat. Через штатный 30-секундный таймаут клиент зарегистрировал `[Session] Server heartbeat timed out; reconnecting` и автоматически вошёл как ID 4. Обработчик восстановлен после подключения. Между остановкой ответов и новым подключением прошло 30,6 секунды (`Logs/net-heartbeat-timeout-start.json`, `Logs/net-heartbeat-timeout-reconnected.json`). Клиент полностью восстановил карту и большой портрет, стол открылся. Хеши портрета совпали (`Logs/net-heartbeat-portrait-recovered.json`); карта/геометрия/туман, владелец и закрытые ХП/КД подтверждены в `Logs/net-heartbeat-timeout-recovered.json`. Этот сценарий подтверждает исправление зависшего живого соединения, но не закрывает проблему повторов карты.

## Согласование повторов карты

Исправлены три причины преждевременного исчерпания попыток: новые части сбрасывают клиентский счётчик последовательных пауз; сервер повторяет незавершённый пакет без дополнительного ожидания финального ACK; продвижение непрерывного диапазона восстанавливает серверный бюджет последовательных сбоев. Отсутствие прогресса и откат не восстанавливают бюджет. Прогресс сообщает непрерывный диапазон частей, чтобы повтор заполнял пропуск, а не начинался после общего числа полученных частей.

4. Незавершённая передача оставляет стол и ввод закрытыми; успешное восстановление открывает только согласованную сцену.
5. Повтор сценариев по локальному транспорту и Relay; полный регрессионный набор.
