# MAP-QA-01 — ход проверки каталога карт

Дата: 10.10.2026. Статус: **В работе**, задача не принята.

## Воспроизведённые ошибки

В MapController.ImportImageFilesToLibrary повреждённые файлы пропускались, а остальные добавлялись. Это не соответствует требованию отказать всему ошибочному пакету без частичных изменений. В SceneFileStore.ImportMapAssets CaptureCampaign выполнялся до проверки изображений: отклонённый импорт мог создать кампанию или обновить её сохранённые снимки. Данные каталога проверялись по форме и размеру Base64, без декодирования изображения.

Unity-проверки на прежнем игровом коде: Logs/map-catalog-before-verified.xml — **2 total, 0 passed, 2 failed**. Пакет с повреждёнными байтами был принят без исключения; пакет с пустым изображением был отклонён, но создал CampaignDefinition. Это подтверждённые ошибки приложения.

Ранние прогоны map-catalog-before.xml, map-catalog-reproduced-before.xml и map-catalog-reproduced-before-direct.xml не считаются воспроизведением ошибок приложения: первый неправильно входил в Play Mode из вложенного IEnumerator, следующие потеряли захваченное состояние проверок при перезагрузке домена. Подготовка исправлена: EnterPlayMode выдаётся из основного теста, проверки с лямбдами вызываются отдельным синхронным методом после входа.

## Изменения

- Сначала проверяются форма, число файлов, размеры отдельных изображений и всего пакета; превышение 96 МБ отклоняется до декодирования и создания текстур.
- Изображения декодируются до изменения данных кампании. Повреждённый файл отклоняет весь пакет.
- Каталог и текущая сцена собираются в отдельной кампании; общий документ и бюджет проверяются перед присваиванием. При отказе прежняя кампания, её снимки и dirty-флаг не меняются.
- Файловый импорт выделен в ImportImagePathsToLibrary, общий для выбранных файлов и папки Editor. Он подготавливает весь пакет перед добавлением; частичного пропуска файлов больше нет.
- Сбор изображений из папки выделен в общий метод с прежними расширениями и сортировкой.
- Итог и ошибка импорта выводятся в панели каталога, дополнительно к краткому уведомлению инструментов.

После первого исправления обе исходные проверки прошли: Logs/map-catalog-after.xml — **2/2, без пропусков**.

## Добавление текущей карты: сохранность при отказе

Logs/map-current-before.xml: **1 total, 0 passed, 1 failed**. После сохранения кампании с картой Original тест задаёт недопустимую ширину сетки 300 и вызывает добавление новой карты. Операция отклоняется, но прежний _currentMapAssetId становится null. Проверка GridManager выполняется через компонент тестового корня, поскольку статического Instance у него нет.

AddCurrentMapAsset теперь декодирует изображение и собирает отдельный кандидат кампании, проверяет документ и бюджет, после чего присваивает кампанию и новый ID карты. При отказе прежняя связь, сохранённые данные и dirty-флаг не меняются. Общий CaptureCampaignCandidate используется также пакетным импортом. XML Logs/map-catalog-six-tests.xml подтверждает **6 total, 6 passed, 0 failed, 0 skipped**, включая отказ добавления текущей карты с сохранением прежней связи и dirty-флага.
